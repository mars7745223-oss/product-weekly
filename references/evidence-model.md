# 证据、研究底座与判断记录

内部核验、结构化台账及《来源与研究说明》使用；不把字段清单、ID或置信度搬进正文。

## 关联对象

新建完整JSON采用[记录契约v2](record-schema.md)，以稳定competitor_id、source_id、event_id、claim_id等规范字段关联。单条任务可使用轻量Markdown；不要求为简单分析建设数据库。旧格式显式备份迁移，禁止将迁移日期改写为事实采集日期。底座是当前竞品状态的参照，初筛/定稿差异用aliases和tier_history表达，不在多个文件保留互相冲突的“当前”状态。

| 对象 | 关键字段 |
|---|---|
| competitor_id | 具体产品/产品线、参照本品、目标任务、竞争层级与理由、地区、有效时间、变更记录 |
| source_id | 主体、入口、源类型、语言/地区、竞品与研究问题、访问方式、状态、最后成功读取及时间精度 |
| event_id | 产品、事件类型、发生/发表/采集日期、地区、型号/版本、交付状态、原始出处、相关旧事件 |
| claim_id | 单一说法、支持与反证、原始位置、适用条件、证据性质、置信度及依据 |
| voice_id | 产品与竞品ID、评论入口和定位、实际短摘录/译文、发表/采集日期、身份、任务、条件、未知项、重复标记 |
| sample_id | 平台/产品、时间窗、排序/检索、浏览/纳入数、排除理由、读取限制、voice_id |
| research_id | 论文/项目、版本与类型、机制、实验与基线、代码/数据及复现状态、已支持阶段、未测项 |
| inference_id | 推断、关联主张、机制或对比桥接、关键假设、不同解释、适用范围、支持/反证及修订历史 |

缺失使用null或“未知”，未知浏览数量不能用0代替。记录时间只能精确到日期时使用日期，不捏造秒数。沿用既有ID；初次可用EVT-YYYYMMDD-01、VOC-YYYYMMDD-01等稳定前缀。关联必须能查到。

不默认建设数据库；两份Markdown可承载轻量记录，已有JSON/表格时更新原台账，不复制长期来源库。

## 主张及推断

分别记录企业声明、用户自述、原始实测、研究、采访与转述。官方资料支持“公司公布”，不单独支持“各地区普遍可用”或“体验良好”。交付状态区分宣布、有限测试、正式交付、研究阶段及未经证实；不适用时留空。

置信度评价具体说法及其条件，不是品牌或文章信誉。用户报告存在可以较确定，故障原因仍可能未知。推断需有支持材料与明确桥接，不能把本品内部需求、资源和痛点作为未声明前提。

评论聚合不计算总体需求、满意率或故障率；不同作者仅说明未发现重复，不证明完全独立。代码提交不等于发布，预印本/专利不等于量产。厂商同源转载不增加独立验证。

## 日期与去重

保留发生、发表、更新与采集日期。区分当周事件、旧事件新增证据和背景；时间来源、时区、相对日期换算与不确定性写入补充文本。正文不使用冗长分类标签，但要保留正确日期与必要阶段，不能把无日期评价写成当周动态。

按主体、产品、版本、地区及语义归并事件；论文预印本/会议/期刊版本关联标识。实际页未读到的检索片段保留线索状态，不能成为已核验评论引文。

## 周度关联与出刊复查

所有正文选中事件进入同一events集合，来源地区不改变记录方式；事件关联claim_ids，主张关联source_ids，推断关联具体claim/voice/research。背景、未刊与窗口外材料也保留状态，不把事件表条数当市场覆盖。出刊前可用`check_issue.py --base`发现外键、日期、Tier和选中事件缺口；脚本不核验网页或解释机制。

沿用 issue、event、claim 和 inference 对象，按实际需要补充字段，不另建重复长期库：

- `weekly_trigger`：本周新增证据 ID、原事件与新进展时间、刊入理由及关联 KIQ；背景标明其支撑作用。
- `updated_at`、`published_timezone`、`time_precision`：原页实际可得值；相对时间保存原文和读取时间，未知不补造。
- `rechecked_at`、`recheck_scope`、`access_status`：当次真实复查时间与范围，未复查字段不继承成功状态；方法更新时间独立。
- inference 的 `evidence_relations`：关联 claim/voice/research ID、关系（支持、冲突、前置条件、机制互补或条件比较）和解释；同周出现不自动建立关系。
- `implication`：具体任务或竞争含义及关键条件；`judgment_change`：建立、支持、削弱、修订或无法判断，关联旧判断，不代替修订历史。

重要状态检查 PR 合并与 release 包含、预发布与正式版、issue 状态与用户环境确认的区别；评测结果与代码当前修订分别记录。来源日期晚于编辑截止时作为窗口外线索；跨截止后采集仍可核验窗口内材料，采集日期如实保留。当前无日期价格只证明读取时页面报价，历史截止价须有相应证据。

## 技术迁移记录的内容

为每条重要迁移推断记录：原问题及机制、原输入/输出、目标应用的输入/输出、成立的同构关系、关键差异、需要的硬件/接口/实时条件、已测与未测的功耗/热/算力等、现有集成或应用证据。单项指标不自动推导完整系统收益，不虚填TRL或商业化时间。

未知集成环节作为分析边界保存，不转成对产品团队的试验任务。正文可以写“可能应用于……，目前证据停留在……”，补充文本说明理由及反证。

## 历史修订与边界

保留旧判断、修订日期、新证据及改变原因。情报问题可以记录待确认事实和缺失来源，不设置产品负责人、实施优先级、实验安排或研发期限。

已有旧版action_id/行动文件只作为历史资料保留，不删除、执行、续写或迁移成新的产品任务。用户另行明确要求的产品工作按其请求独立处理，不属于本skill默认交付。

## 3.0研究底座与扩展对象

长期底座可保存在本品目录`研究底座.json`，每期证据以相对路径引用，继续使用原来源台账。轻量单条任务可用Markdown表达同一关系，不强制建设全套文件。下列对象补充现有ID，不复制来源/原声或取代原主张。

| 扩展对象 | 记录内容 |
|---|---|
| scope_id / kiq_id | 读者、参照本品、任务、人群、地区、研究期限；问题、公开或用户给定依据、假设与未知；研究期限与新闻窗口分开 |
| competitor_id | 研究粒度、父级公司/产品线、五维竞争关系、六类多标签、资格状态、Tier及Benchmark属性；这些字段与正文栏目分开 |
| assessment_id | CPS/TOS、权重版本、明确参照、各维分或null、证据引用、理由与反证、覆盖率、完整分/范围、排序敏感性、评估日期 |
| profile_id | 竞品ID、KIQ、14维模块、重点问题、L1–L3目标深度/已完成状态、基线有效日期、能力及商业机制依据 |
| capability_id | 具体能力、产品/版本/地区、宣称、证据类型、能力可用阶段、主张引用；不继承整机上市状态 |
| technology_id | 原research_id、问题来源、功能标签、四类迁移、跨行业案例、原/目标输入状态输出约束、双域阶段、系统条件和可获得性 |
| judgment_id | 原inference_id、机制桥接、竞争含义、假设条件、研究期限、外部支持/反证信号、复核状态与修订历史 |

profile是长期档案，issue记录基线日期、旧事件日期、新证据日期、本期增量及刊入理由。方法改版不使旧消息变新；旧稿与重编也不是两次独立交付。

## 信息状态与核验范围

台账和补充文本区分四状态：已核实事实、估算数据、分析推断、未核验说法。来源获取状态、证据性质、来源质量及判断置信度分别保存；正文仍用自然措辞限定。

核实“厂商宣布X”不等于核实“X稳定有效”。估算须记录输入、公式、时间、单位、分母、基线与假设。用户自述存在与其工程原因是不同主张；研究阶段不能被商用可得性替代。财务、市场份额、招聘人数等未披露时保持未知，未见公开投入不能写成没有投入。

能力状态可为宣称、公开展示、有限条件使用、正式可用、撤回/停用、未知。与产品的宣布/交付状态分别记录。未取得能力资料记“未确认”，不认定“能力不存在”；全部适用条件可定位到claim_id。

比较须核对任务、产品层级、版本、地区、时间与指标口径。眼镜价与整套配件成本、预约金与整机价、宣传峰值与持续实测分开。20→12分钟是时长减少40%；若同等条件下比较吞吐，提高约66.7%，不能笼统称“效率提高40%”。

## 可选评分与算术校核

按[竞品选择](competitor-selection.md)和[技术分析](research-to-product.md)确定模型与评分依据。1–5分映射20–100，不是概率、份额或威胁百分比。已评分维度必须有明确参照、理由和证据引用；缺失为null，不填1/3、不按剩余维度归一化、不用置信度折分。覆盖为0时不展示分数区间；不完整分不能与完整分混排。

标准库脚本只校核结构和算术，不读取网页或决定Tier、刊入、采用或投资：

```text
python scripts/score_priority.py 已有评分输入.json
python scripts/score_priority.py 已有评分输入.json --output 评分计算结果.json
```

输入含`model`（CPS/TOS）、`scope`、`ratings`；每个rating含`score`、`reason`、`evidence_refs`。改权重时提供完整`weights`及`weight_version`，权重合计1。输入格式见[评分模板](../assets/priority-input-template.json)。输出覆盖率、完整分/范围及单维辅助分；字段存在不证明来源真实，关键评分仍需人工核验。

用于对象比较时，可用`--sensitivity 权重情景.json`复算有理由的完整权重情景；输出仍是算术，不自动修改Tier或给出采用排序。已知分数的评审分歧与权重选择另存，缺失维度上下界不是统计置信区间。首页排名按覆盖与优先级参考保存独立理由。

## 覆盖、编辑与效果记录

coverage_plan记录origin、锁定时间、版本与检查单元；执行状态和实际已读范围与原source关联。事后修复只能称retrospective。editorial保存首页rank、关联、具体理由、影响和证据性质，排除候选保存理由。采用模板见[期记录模板](../assets/issue-record-template.json)。

效果评估不默认加入每期生产。执行时记录任务/模型/工具/权限/预算、参考集构成、原始计数、人工干预、查证与维护成本。未经测量为null或未评估；格式、代码、结构、版式与事实/召回/读者价值检查分别报告，不能相加为整体准确率。

## 条件假设与兼容迁移

未来竞争假设与已发生事件分开，保留触发条件、时间范围、可观察的支持/反证、替代解释。复核状态可为待核验、获得支持、出现反证、已修订、已到观察期限、无法判断。没有观察到公开信号不等于它不存在；到期或获得支持不自动变成确定事实；不为重叠情景硬凑100%概率。

扩展旧台账时schema版本与方法版本分开，保留旧ID、字段、日期、阶段及行动历史。新增字段有材料才填；没有则null/待评估。方法复核时间不覆盖最后事实核验或采集时间；迁移记录注明旧/新schema、处理对象、时间及未新增事实。重新出刊需另有当次任务，不能悄悄改已刊正文。
